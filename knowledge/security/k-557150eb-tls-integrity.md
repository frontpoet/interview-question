# TLS 身份认证与传输完整性

## 核心概念

HTTPS 使用 TLS 提供对端认证、机密性和完整性。“不被篡改”准确地说是：在信任链与端点未失陷时，攻击者改动的数据无法通过验证并被当成有效数据接受。

## 原理与机制

握手验证证书链、域名和有效期，并证明对端持有相应私钥；密钥协商产生会话密钥。TLS 1.3 使用 AEAD 保护记录，篡改会导致认证标签验证失败并中止连接。握手 transcript 的验证也防止握手参数被悄悄替换。依据：[RFC 8446 §4、§5](https://www.rfc-editor.org/rfc/rfc8446.html)。

## 适用边界与易错点

DNS/路由被改只能把连接导向别处，不能自动取得目标域名的合法认证能力；攻击者仍可丢包或阻断服务。忽略证书错误、安装恶意根证书、终端或合法服务器被控制时，上述前提失效。可信代理终止 TLS 后，保护边界到代理为止；HTTPS 不证明服务器内容本身可信，也不能代替 XSS 防护。
