# 配额、限流与并发控制

## 核心概念

配额限制累计资源占用；限流限制时间窗口内到达量；并发控制限制同时占用的资源槽位。三个限制不能互相替代。

## 原理与机制

- 文件数量配额：在事务或原子操作中检查“已完成 + 已预留 < 上限”并预留，成功后转为已完成，失败或过期时回收。
- 并发上限：使用信号量或有所有者的租约槽位，申请成功才开始，完成后释放；多实例须使用共享协调状态。
- 速率限制：令牌桶允许受控突发，滑动窗口约束一段时间的请求量；按账号、租户及必要的 IP 维度计数。
- 幂等请求：同一上传 ID 或幂等键重试不得重复占额。释放必须匹配租约所有者，不能让迟到请求释放新任务的槽位。

## 适用边界与易错点

“先查数量再加一”会被并发请求同时穿过。租约过期若旧任务仍在执行，会造成超额；必须续租，并在租约丢失时中止任务或用 fencing token 拒绝旧任务提交。Redis Lua 的原子性只覆盖脚本访问的数据，不等于跨数据库、对象存储的事务。对象存储直传也要在签发上传凭证与最终确认时检查配额。
