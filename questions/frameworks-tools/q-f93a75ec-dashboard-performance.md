# 大屏项目如何进行持续运行的性能优化？

## 题目

数据可视化大屏加载慢、实时刷新卡顿，且运行久了内存上涨，如何优化？

## 简要回答

- 固定测试设备、屏幕分辨率、数据量与刷新频率，用 Performance 录制定位网络、主线程计算、布局绘制或 GPU 瓶颈。
- 首屏拆分重型图表代码、压缩资源、并行取得独立数据并缓存适合缓存的响应。
- 持续更新使用增量数据、降采样、有界队列和批量提交，避免每条推送触发所有图表更新。
- 昂贵计算使用 Worker；减少重复创建图表、深拷贝和无效框架更新；读写布局分开，避免强制同步布局。
- 按数据密度选择 SVG、Canvas、WebGL；控制像素比、点数、动画和透明叠加的成本。
- 定期检查内存快照，释放图表、事件、计时器和连接；页面隐藏时降频，恢复时处理过期数据。

## 分析与边界

比较修改前后的帧耗时、长任务、交互延迟、消息积压和长期内存曲线。60Hz 屏幕每帧约 16.7ms 是总预算而非 JS 独占预算；优化不能让关键事件丢失或数据时效不达标。此题侧重持续运行，可与通用首屏优化题结合复习。
