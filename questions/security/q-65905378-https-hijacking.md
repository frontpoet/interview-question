# HTTPS 遭遇网络劫持后，为什么能发现篡改？

## 题目

HTTPS 在 DNS、路由或链路被劫持后，为什么通常仍能防止内容被悄悄篡改？

## 简要回答

- 证书与握手验证确认目标域名对应的服务端身份，防止攻击者冒充。
- 会话数据使用带认证的加密；没有会话密钥，攻击者难以伪造可通过校验的记录。
- 被修改的记录会被拒绝，连接可能失败；并非物理上不能改动网络中的字节。
- 这不保证可用性，也不覆盖恶意根证书、忽略证书错误、端点失陷或可信 TLS 代理内部的修改。

## 常见问法

“https 在劫持之后为什么能不被篡改？”此处把劫持限定为网络路径被控制；若浏览器信任根也被控制，结论不同。
