# 如何介绍最满意的项目背景、个人贡献与亮点？

## 题目

讲一个做得比较满意的项目，说明项目背景、个人产出贡献和亮点。

## 简要回答

按“谁遇到什么问题 → 我的职责 → 一个关键决策 → 如何落地验证 → 结果与不足”讲述，优先选自己能解释清楚设计和取舍的真实项目。

## 回答组织示例

以下是待填写的结构，不是用户实际经历：

- 背景：为【用户】解决【具体问题】，受【时间、设备、数据量等】约束。
- 职责：我独立负责【模块/流程】，与【角色】协作；团队其他部分由【角色】承担。
- 关键行动：比较【方案 A/B】，因为【约束或实验结果】选择【方案】，处理【一个难点】。
- 产出：交付【功能、文档、测试、监控等】，用【验收办法】确认达到目标。
- 结果与亮点：在【同一口径】下从【基线】变为【结果】；没有测量就用真实反馈或已完成能力说明。
- 反思：仍存在【限制】，如果重做会优先改进【具体事项】。

## 分析与边界

通常先给约两分钟主线，再准备架构、失败方案、代码细节和结果证据供追问。亮点应解释为何解决了难题，不以“用了某热门框架”代替贡献。原题未提供个人项目事实，本文只提供可直接用于准备的框架。
