# 服务器如何限制上传文件数量、并发与频率？

## 题目

服务器限制上传数量怎么实现？原题未明确“数量”，分别讨论每次文件数、用户总量、并发数和请求频率。

## 简要回答

1. 单次最多 N 个文件：服务端解析上传表单时强制限制，同时限制单文件及总字节数；前端校验用于及时反馈。
2. 用户最多 N 个文件：以用户为键，原子检查并预留额度，上传完成后确认；失败回滚、超时回收，幂等重试不重复计数。
3. 同时最多 N 个任务：客户端任务队列只改善体验，服务端仍需信号量或共享租约控制，多实例不能各自独立计数。
4. 每分钟最多 N 次：使用限流器；触发速率限制通常返回 429 和可选 Retry-After，客户端按约定退避。
5. 分片按 uploadId 聚合，明确额度是“文件任务”还是“分片请求”；直传存储也不能绕开服务端授权和完成校验。

## 分析与边界

假设限制按账号生效，关键操作为“校验权限 → 原子预留 → 上传 → 校验并确认”，异常路径都要可恢复。配额耗尽、服务繁忙和格式错误应有不同业务错误，不能全当 429。预留租约若到期，旧任务不得继续消耗或提交资源；需续租、取消及过期清理。
