# 直播比赛中如何实时加载评论？

## 题目

为直播比赛设计实时评论，兼顾大量观众、断线重连和前端渲染性能。

## 简要回答

假设是文字评论下发，发送频率低于接收频率，可采用 HTTP 发评论 + SSE 广播；需要频繁双向互动时改用 WebSocket。

1. 首次加载历史快照与游标，再从该游标订阅增量，避免历史加载和订阅之间漏消息。
2. 服务端鉴权、校验内容、限流，持久化后按房间广播；多实例通过消息系统分发，热门房间需要分片扇出。
3. 每条评论包含 ID、房间和序号；重连用游标补拉，客户端去重，发现缺口时恢复历史。游标失效则重新拉快照。
4. 客户端有界缓冲、按批次渲染，长列表虚拟化；用户向上读历史时不强制滚到底部，显示新消息数量。
5. 安全输出文本，处理审核、撤回、发送失败与乐观消息的确认映射；离页释放连接和监听器。

## 分析与边界

“实时”需约定延迟目标和峰值量，不能无限保存 DOM 或消息。高峰可降低展示频率或只展示采样评论，但要说明这是产品降级，不能把丢弃当作可靠交付。评论系统和视频分发链路分别设计；应测量端到端延迟、重连补齐率、队列长度及掉帧。
